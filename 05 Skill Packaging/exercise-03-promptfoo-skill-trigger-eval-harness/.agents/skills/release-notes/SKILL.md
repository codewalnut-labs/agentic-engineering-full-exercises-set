# Release Notes

1. Inspect only the requested release range, merged pull requests, and supplied evidence.
2. Group shipped changes by user impact.
3. Call out missing or conflicting evidence instead of inventing details.
4. Produce concise reviewer-ready release notes with source identifiers.

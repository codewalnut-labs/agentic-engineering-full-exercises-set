# Principles for this exercise's Spec Kit constitution

- Read the supplied request, stakeholder notes, billing constraints, and existing source before making claims.
- Distinguish current technical facts, approved product decisions, provisional assumptions, and unanswered questions.
- Do not invent stakeholder approval. Preserve unanswered high-impact questions even if a command suggests a default or reaches its clarification limit.
- Define user-visible outcomes, scope, measurable success criteria, and failure/boundary scenarios.
- A generated checklist needs a separate review. A checked box must have a source-backed assessment.
- Keep native feature documents and the review trail. Report Needs decisions while blockers remain.
- Stop after specification, clarification, checklist review, and revision. Do not implement application code or modify protected starter inputs.

These principles customize the workflow for this challenge; they do not supply product-policy answers. Record any differences from upstream defaults in the workflow inventory.
